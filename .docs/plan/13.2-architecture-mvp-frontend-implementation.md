# 13.2 — MVP Frontend Implementation Plan

> Frontend implementation for the routes, controllers, and data model defined in `13.1-architecture-mvp-implementation.md`.
> Follows `.github/copilot-laravel-inertia-react-instructions.md` and `.github/copilot-react-instructions.md`.

---

## Guiding Principles

1. **Backend owns logic** — all validation, auth, data shaping happens in Laravel controllers (already built).
2. **Inertia = transport** — pages receive typed props, mutations use the Inertia router.
3. **React = UI + interaction** — rendering, local UI state, minor derived values only.
4. **Mobile-first** — all layouts built for small screens first, enhanced at `sm:`/`md:` breakpoints.
5. **Feature-based structure** — code grouped by domain, not by type.

### Key decisions

- **`features/`** holds domain components and hooks — never pages.
- **`Pages/`** stays as the Inertia page resolver target (`./Pages/${name}.tsx`). Pages are thin: import from `features/`, compose, render.
- **`shared/`** only for genuinely reusable, non-domain utilities.
- **Breeze `Components/`** kept as-is — they're generic UI primitives.

### 3.1 `Pages/Daily/Index.tsx` — Daily View

**Route**: `GET /daily` → `DailyController@index`
**Props**: `{ date: string, moments: DailyMoment[] }`

```
┌────────────────────────────────────────┐

│                                        │
│  ┌──────────────────────────────────┐  │

│  │ ░░░░░░░░░░░░░░░░░░░░░░  ☐      │  │
│  └──────────────────────────────────┘  │
│                                        │
│  ┌──────────────────────────────────┐  │
│  │ 📚 Read a book           🔥 0   │  │
│  │ ░░░░░░░░░░░░░░░░░░░░░░  ☐      │  │
│  └──────────────────────────────────┘  │
│                                        │
│          [ + New Moment ]              │
│                                        │
└────────────────────────────────────────┘
```

**Behaviour**:
- Each `MomentCard` shows icon, name, streak badge, and a toggle checkbox.
- Tapping the checkbox calls `POST /moments/{id}/toggle` via `axios.post()` (JSON endpoint, not Inertia visit).
- Optimistic UI: flip checkbox immediately, revert on error.
- "New Moment" links to `/moments/create`.
- Empty state shown when `moments.length === 0`.

**Why axios, not `router.post()`?**
The toggle endpoint returns JSON (`{ completed_at, instance_id }`), not an Inertia page redirect. Using `axios` keeps the page in place and avoids a full page reload. We update local state from the JSON response.

### 3.2 `Pages/Moments/Create.tsx` — Create Moment

**Route**: `GET /moments/create` → `MomentController@create`
**Props**: none (empty form)

Uses `MomentForm` from `features/moments/`. Form submits via `router.post(route('moments.store'), data)`.

### 3.3 `Pages/Moments/Edit.tsx` — Edit Moment

**Route**: `GET /moments/{moment}/edit` → `MomentController@edit`
**Props**: `{ moment: Moment }` (with schedule, cue, reward eager loaded)

Uses the same `MomentForm` with populated defaults. Submits via `router.put(route('moments.update', moment.id), data)`.
Includes a delete button: `router.delete(route('moments.destroy', moment.id))` with confirmation modal.

### 3.4 `Pages/Config/Edit.tsx` — Settings

**Route**: `GET /config` → `ConfigController@edit`
**Props**: `{ config: UserConfig }`

Simple form with wake time, sleep time, week start day. Submits via `router.put(route('config.update'), data)`.

### 4.8 `features/moments/hooks/useMomentForm.ts`

```ts
import { useForm } from '@inertiajs/react';
import { Moment, MomentFormData } from '../types';

const defaults: MomentFormData = {
    name: '',
    description: '',
    color: '#3B82F6',
    icon: '',
    identity_statement: '',
    sort_order: 0,
    is_active: true,
    frequency: 'daily',
    days_of_week: [],
    preferred_time: '',
    implementation_intention: '',
    habit_stack_after: '',
    environment_prompt: '',
    reward_description: '',
    temptation_bundle: '',
};

export function useMomentForm(moment?: Moment) {
    return useForm<MomentFormData>({
        ...defaults,
        ...(moment ? {
            name: moment.name,
            description: moment.description ?? '',
            color: moment.color ?? '#3B82F6',
            icon: moment.icon ?? '',
            identity_statement: moment.identity_statement ?? '',
            sort_order: moment.sort_order,
            is_active: moment.is_active,
            frequency: moment.schedule?.frequency ?? 'daily',
            days_of_week: moment.schedule?.days_of_week ?? [],
            preferred_time: moment.schedule?.preferred_time ?? '',
            implementation_intention: moment.cue?.implementation_intention ?? '',
            habit_stack_after: moment.cue?.habit_stack_after ?? '',
            environment_prompt: moment.cue?.environment_prompt ?? '',
            reward_description: moment.reward?.description ?? '',
            temptation_bundle: moment.reward?.temptation_bundle ?? '',
        } : {}),
    });
}
```

## 8. Implementation Order

Build bottom-up: types → shared → features → pages → layout.

| Step | Files | Why |
|---|---|---|
| 1 | Type files (4) | Foundation — everything depends on these |
| 2 | `shared/` components (3) | FlashMessage, EmptyState, dates util |
| 3 | `features/daily/` (3) | MomentCard, StreakBadge, barrel |
| 4 | `Pages/Daily/Index.tsx` | First working page — verify end-to-end |
| 5 | `features/moments/` (7) | Form components + hook |
| 6 | `Pages/Moments/Create.tsx` + `Edit.tsx` | Moment CRUD pages |
| 7 | `features/config/` + `Pages/Config/Edit.tsx` | Settings page |
| 8 | `AuthenticatedLayout.tsx` updates | Nav links, user name |
| 9 | Login redirect to `/daily` | Final wiring |

Each step is independently testable — after step 4 you have a working daily view.

## 9. Styling Approach

- **Tailwind CSS** — utility-first, no custom CSS files per component.
- **Mobile-first** — base styles for `< 640px`, enhance with `sm:`, `md:`, `lg:`.
- **Color theming** — moment colors used as accent via inline `style={{ backgroundColor }}` or Tailwind arbitrary values.
- **Dark mode** — deferred to post-MVP.
- **Animations** — checkbox toggle gets a subtle scale/opacity transition. Streak badge pulses on increment. Keep lightweight.

---

## 10. Anti-Patterns to Avoid

Per the project's Copilot instructions:

| ❌ Don't | ✅ Do Instead |
|---|---|
| `useEffect(() => setMoments(props.moments), ...)` | `const moments = props.moments` |
| Business logic in React (streak calc, scheduling) | Backend computes, frontend displays |
| `any` types | Typed props from `features/*/types.ts` |
| Fat page components (300+ lines) | Import from `features/`, compose in page |
| `fetch()` or `axios` for Inertia routes | `router.post()` / `router.put()` / `router.delete()` |
| `axios` for Inertia redirects | Only use `axios` for JSON endpoints (`toggle`) |
| Cross-feature imports | Move to `shared/` if needed by 2+ features |
| Duplicating validation in React | Backend validates — frontend shows `errors` from Inertia |

## 11. Post-MVP Frontend (Not Now)

Documented here for awareness — **do not build these yet**:

- **Weekly view** (`Pages/Weekly/Index.tsx`) — M T W T F S S grid, click-to-drill
- **Dashboard** (`Pages/Dashboard/Index.tsx`) — charts, monthly %, top habits
- **Drag-to-reorder** moments (sort_order via `PATCH`)
- **Dark mode** toggle
- **PWA / offline** — service worker for cached daily view
- **Notifications** — push reminders for scheduled moments
- **Friction slider** — easy ↔ hard UI on moment creation
