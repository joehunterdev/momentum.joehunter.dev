# 13.3 — MVP Frontend Styles Implementation Plan

> SCSS architecture and design strategy for the Momentum habit tracker.
> Builds on `13.2-architecture-mvp-frontend-implementation.md`.
> Inspired by Joe Hunter's project style (grab-it) — dark gradients, bold accents, spatial typography.

---

## Guiding Principles

1. **Tailwind first** — utility classes handle 80% of styling inline. SCSS handles the remaining 20%: global tokens, complex states, animations, and dark-mode theming.
2. **SCSS for structure, not duplication** — never rewrite a Tailwind utility in SCSS. Use SCSS for things Tailwind can't do cleanly: CSS custom properties, keyframe animations, multi-property transitions, complex pseudo-element patterns.
3. **Design tokens as CSS variables** — all colours, spacing scales, and typography values live as `--mm-*` custom properties in `:root`. Components reference tokens, not raw values.
4. **Dark-mode native** — Momentum ships dark by default (matching grab-it aesthetic). Light mode is a future toggle via `[data-theme="light"]`.
5. **Mobile-first** — base styles target phones. Breakpoints enhance upward.

---

## 1. SCSS File Architecture

Rename `resources/css/app.css` → `resources/css/app.scss` and restructure:

```
resources/css/
├── app.scss                         # Entry point — imports everything
├── _variables.scss                  # Design tokens (CSS custom properties)
├── _base.scss                       # Reset, body, typography, scrollbar
├── _animations.scss                 # Keyframes & transition utilities
├── _components.scss                 # Reusable component patterns
└── _pages.scss                      # Page-specific overrides (minimal)
```

### Why this structure?

- **Flat partials** — no nested folders. This is an MVP with < 10 files. Keep it scannable.
- **Underscore prefixed** — standard SCSS convention for partials, won't compile alone.
- **Single entry point** — `app.scss` imports Tailwind layers + all partials in order.

## 10. Migration Strategy — Tailwind ↔ SCSS

| Concern | Use Tailwind | Use SCSS class |
|---|---|---|
| Layout, spacing, flex/grid | ✅ `flex gap-3 p-4` | ❌ |
| Text colour, font size | ✅ `text-mm-text text-sm` | ❌ |
| Simple backgrounds | ✅ `bg-mm-surface` | ❌ |
| Borders, radius | ✅ `border border-mm-surface rounded-mm` | ❌ |
| Gradient backgrounds | ❌ | ✅ `.mm-btn-primary` |
| Multi-state transitions | ❌ | ✅ `.mm-toggle`, `.mm-moment-card` |
| Keyframe animations | ❌ | ✅ `.mm-animate-check` |
| Pseudo-elements (::before) | ❌ | ✅ `body::before` pattern |
| Glassmorphism (backdrop-filter + layered bg) | ❌ | ✅ `.mm-card` |
| Focus ring consistency | ❌ | ✅ global `*:focus-visible` |
| Dark mode overrides for forms plugin | ❌ | ✅ `.mm-input` |

**Rule of thumb**: If a style needs more than 4 Tailwind utilities chained together, or involves animation/pseudo-elements, use an SCSS class.

## 11. Design Language Summary

Inspired by grab-it's dark UI but adapted for a habit tracker:

| Aspect | grab-it | Momentum |
|---|---|---|
| Background | `#0a0e27` dark blue | `#0F172A` slate-900 (warmer) |
| Primary accent | `#00d4ff` cyan | `#6366F1` indigo (calmer, habit-appropriate) |
| Success/complete | `#00ffaa` green | `#10B981` emerald (softer) |
| Card style | `rgba(0,0,0,0.4)` + border | Glassmorphism + `backdrop-filter: blur` |
| Corners | `border-radius: 0` (sharp) | Rounded (`12px–20px`) — friendlier for daily use |
| Animation easing | `cubic-bezier(0.34, 1.56, 0.64, 1)` | Same — bouncy micro-interactions |
| Typography | Titillium Web 900 | Figtree / Inter — cleaner for data-heavy UI |
| Pattern overlay | SVG crosses at 3% opacity | SVG grid at 3% opacity |

## 13. Implementation Order

| Step | What | Why |
|---|---|---|
| 1 | Create `_variables.scss` + `_base.scss` | Foundation — everything else references these |
| 2 | Create `_animations.scss` | Needed by component classes |
| 3 | Create `_components.scss` | The bulk of the custom styles |
| 4 | Create `_pages.scss` | Thin page overrides |
| 5 | Rename `app.css` → `app.scss`, add imports | Wire it all together |
| 6 | Update `app.tsx` import | Point to `.scss` |
| 7 | Extend `tailwind.config.js` | Enable `bg-mm-*`, `text-mm-*` utilities |
| 8 | Update React components to use new classes | Swap inline Tailwind → SCSS where beneficial |

Step 8 can be done incrementally — components will still work with plain Tailwind until they're migrated to the new design.

---

## 14. Anti-Patterns

| ❌ Don't | ✅ Do Instead |
|---|---|
| Create a `.scss` file per component | One `_components.scss` with BEM-ish classes |
| Duplicate Tailwind in SCSS (`.mt-4 { margin-top: 1rem }`) | Use Tailwind utilities or `@apply` sparingly |
| Hard-code colours in component `.tsx` files | Reference `var(--mm-*)` or `text-mm-*` |
| Use `!important` everywhere | Only in `_components.scss` for form plugin overrides |
| Deep nesting (> 3 levels) | Flat BEM: `.mm-card`, `.mm-card--active` |
| `@apply` for everything | Only for 4+ utility compositions that repeat often |

## 15. Post-MVP Styles (Not Now)

- **Light mode** — flip via `[data-theme="light"]` on `<html>`, toggle in Settings
- **User-customisable accent** — store as `user_config.accent_color`, inject via inline `--mm-primary`
- **Charts/visualisations** — SVG fill colours from tokens
- **PWA splash screen** — gradient matching `--mm-bg-gradient`
- **Print styles** — minimal, no gradients, light backgrounds
